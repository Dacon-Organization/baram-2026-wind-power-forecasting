# 06. 전처리 가드레일 — 무엇이 허용되고 무엇이 금지인가

> 작성일: 2026-07-27 KST
> 버전: v1.0
> 상태: 운영 기준 확정
> 선행 문서: [05-feature-set-promotion.md](05-feature-set-promotion.md)
> 범위: 이 저장소의 전처리·검증이 실무 기준과 대회 규정에서 방어 가능한지 판단하는 기준.
> 범위 밖: 모델 선택, 하이퍼파라미터, 피처 아이디어 자체의 타당성.

## 0. 한 장 요약

| 구분 | 핵심 |
|------|------|
| 전제 | 전처리 실수는 **에러를 내지 않는다.** 점수만 조용히 좋아지고, 그 점수는 제출 시점에 무너진다 |
| 판별 기준 | "이 값을 계산할 때 **예측 시점에 알 수 없는 정보**가 한 방울이라도 들어갔는가" |
| 절대 금지 | 예보 가용 시각 이후 정보, test/holdout 통계로 fit, 라벨 파생 피처, 규정 위반 (2절) |
| 조건부 허용 | 대치·스케일링·보간·피처 선택 — **fit 범위를 train으로 가두면** 전부 허용 (3절) |
| 우리 방어선 | 규율이 아니라 **구조**로 막는다. 위반이 예외로 드러나게 만든다 (4절) |
| 과적합 | 같은 holdout을 반복 사용하면 추정치가 낙관 편향된다. 현재 위험도는 낮으나 후보가 늘면 커진다 (5절) |
| 용어 | validation과 test, lead time과 cutoff를 혼동하면 설명이 무너진다 (6절) |

## 1. 이 문서를 쓰는 이유

모델링 실수는 대개 시끄럽다. 형태가 안 맞으면 예외가 나고, 라벨이 없으면 학습이 멈춘다.
그런데 **전처리 누수는 조용하다.** 코드는 정상 종료하고, 검증 점수는 오히려 올라간다.
문제를 알아채는 시점은 보통 리더보드 점수가 local과 크게 어긋난 뒤이며, 그때는 어느 단계에서
새어 들어왔는지 되짚기 어렵다.

발표나 코드 리뷰에서 "이 전처리는 왜 괜찮은가"를 묻는 질문에 답하려면, 판단 기준이
사람의 주의력이 아니라 문서와 코드에 있어야 한다. 이 문서가 그 기준이다.

**하나의 판별 질문으로 압축된다.**

> 이 값을 계산할 때, **예측 시점에는 알 수 없었을 정보**가 한 방울이라도 들어갔는가?

들어갔다면 금지다. 안 들어갔다면 허용이다. 아래 절은 이 질문을 상황별로 풀어 쓴 것이다.

## 2. 절대 금지 (Hard No)

fit 범위를 조정해도 정당화되지 않는 항목이다.

### 2.1 예보 가용 시각 이후의 정보 사용

이 대회의 NWP는 `forecast_kst_dtm`(예보 대상 시각)과 `data_available_kst_dtm`(예보가
실제로 손에 들어온 시각)을 함께 준다. 후자가 전자보다 늦은 행을 쓰면, 실제 운영에서는
아직 존재하지 않는 예보로 과거를 맞히는 셈이 된다.

이것이 시계열 특유의 누수인 **look-ahead bias**이며, Lones가 정리한 ML 함정 목록에서
시계열 항목의 첫 번째로 지목된 것이다.

**우리 방어:** `src/baram/baseline.py:63`의 `_validate_weather_cutoff()`가 집계 전에
`data_available_kst_dtm > forecast_kst_dtm`인 행을 세어 하나라도 있으면
`ValueError`를 던진다(`baseline.py:73`). 조용히 걸러내지 않고 **실행을 멈춘다.**

### 2.2 test·holdout 데이터로 통계를 fit

평균·중앙값·표준편차·최소/최대·PCA 성분·클러스터 중심 — 무엇이든 **평가 대상 구간의
값이 들어간 통계**를 학습 파이프라인에 쓰면 안 된다.

"이건 라벨이 아니라 입력이니 괜찮다"는 반론이 흔하지만, Moscovich와 Rosset은
**비지도(unsupervised) 전처리조차** resampling loop 밖에서 파라미터를 추정하면
교차검증 추정치에 상당한 편향이 생긴다는 것을 이론과 실험으로 보였다.
전체 데이터에 스케일러를 fit하고 나중에 나누는 관행이 여기 해당한다.

**우리 방어:** 3절과 4절 참조. imputer도 공간 pooler도 train 구간에만 fit한다.

### 2.3 라벨에서 파생한 값을 같은 라벨의 피처로 사용

target encoding, 그룹별 라벨 평균, 라벨 기반 이상치 제거가 대표적이다.
같은 행의 라벨이 그 행의 피처에 스며들면 검증 점수는 거의 완벽해지고 제출 점수는 무너진다.

**우리 상태:** 이 저장소는 라벨 파생 피처를 **하나도 쓰지 않는다.** 피처는 전부 NWP 격자와
달력에서만 나온다. `calendar_features()`(`baseline.py:116`)의 docstring이 "target 시각에서
leakage 없는 calendar feature"라고 계약을 명시한다 — 시각 자체는 예측 시점에 이미 아는 값이다.

### 2.4 test 예측값을 다시 학습에 투입

self-training이나 pseudo-labeling을 리더보드 피드백과 함께 돌리면, 사실상 test 라벨을
간접적으로 학습하는 것이 된다. 대회 종료 후 Private 점수에서 무너진다.

**우리 상태:** 사용하지 않는다.

### 2.5 대회 규정 위반

| 항목 | 규정 |
|------|------|
| 외부 데이터 | 공식 배포 자료 외 데이터는 사실로 승격하지 않는다 (`docs/README.md` 작성 원칙) |
| 원격 API 추론 | 규정상 금지이므로 설계 후보에서 제외한다 (같은 문서) |
| 원자료 재배포 | `data/raw/open/`은 로컬 보관만, Git 커밋 금지 (`AGENTS.md`) |

외부 리서치는 **모델 아이디어와 시장 조사**에는 쓸 수 있지만, 대회 데이터에 관한
사실 주장으로 승격시키지 않는다는 것이 이 프로젝트의 기존 규칙이다.

## 3. 조건부 허용 — fit 범위만 지키면 된다

아래는 **금지 항목이 아니다.** 흔히 "하면 안 되는 것"으로 오해되지만, 실제 규칙은
"하지 마라"가 아니라 **"train에만 fit하고 나머지엔 transform만 하라"**이다.

| 전처리 | 허용 여부 | 지켜야 할 것 |
|--------|-----------|--------------|
| 결측 대치 (mean/median/최빈값) | 허용 | 대치값 통계를 train에서만 계산 |
| 스케일링·정규화·표준화 | 허용 | 스케일러를 train에만 fit |
| 로그·Box-Cox 등 단조 변환 | 허용 | 파라미터가 있는 변환이면 train에서만 추정 |
| 공간 보간 (IDW, nearest) | 허용 | 가중치를 train 격자 geometry에서만 계산 |
| 차원 축소 (PCA 등) | 허용 | 성분을 train에서만 학습 |
| 피처 선택 | 허용 | **분할 이후**에, train만 보고 선택. Lones가 그림으로 경고한 지점 |
| 이상치 제거 | 조건부 | train 행만 제거. **test 행은 지우지 않는다** — 제출 행 수가 고정이다 |
| 리샘플링·집계 | 허용 | 시각 경계를 넘지 않을 것 |

### 3.1 결측을 "메우는" 것과 "복원하는" 것은 다르다

2025년 test에는 LDAPS forecast-variable 쌍 47개가 전 격자 결측이고, 조립 후 기준으로
**550개 컬럼 중 133개(24%)에 NaN이 있다**(설계서 05 R5, 노트북 10 5-2절).

여기서 유혹이 생긴다 — 공간 pooling으로 이웃 격자 값을 끌어와 메우면 결측이 사라진다.
그러나 그것은 **없는 관측을 만들어내는 것**이지 복원이 아니다. 우리는 NaN을 그대로 보존한
뒤 train에서 fit한 median으로만 채우고(`weather_grid.py:233` 주석에 계약으로 명시),
그 사실을 노트북에 기록해 점수 해석 시 함께 읽도록 했다.

즉 **2025년 제출용 피처의 4분의 1은 관측이 아니라 2022~2024년 중앙값이다.**
이 문장을 숨기지 않는 것이 가드레일의 일부다.

## 4. 이 저장소가 실제로 지킨 방법 — 코드 대응표

원칙을 문서에만 두면 지켜지지 않는다. **위반이 예외로 드러나도록 구조에 심는 것**이
이 프로젝트의 방식이다.

| 위험 | 방어 장치 | 위치 |
|------|-----------|------|
| look-ahead (예보 가용 시각) | cutoff 위반 행이 있으면 즉시 `ValueError` | `baseline.py:63`, `:73` |
| imputer가 test를 봄 | `SimpleImputer`를 train feature matrix에만 fit, test는 transform만 | `baseline.py:206` |
| 공간 pooler가 test 격자를 봄 | pooler를 train raw 행에만 fit | `feature_pipeline.py:83`~`:104` |
| 격자 geometry가 몰래 바뀜 | transform 시 grid_id·좌표를 fit 당시와 대조, 다르면 예외 | `turbine_spatial.py:210` |
| train/test 피처가 어긋남 | 조립 마지막에 컬럼 이름·순서 동일성을 사후 조건으로 강제 | `feature_pipeline.py:311` |
| 결측을 임의로 복원 | 전 격자 NaN은 NaN으로 보존한다고 계약에 명시 | `weather_grid.py:233` |
| 실제값을 손대서 점수를 올림 | clip을 **예측에만** 적용, 실제값은 원본 유지 | `baseline.py:256` |
| 전처리가 바뀌었는데 기록이 같음 | `preprocessing_sha256`를 config에서 파생 | `registry.py`, 노트북 09 5절 |
| train/inference 피처셋 불일치 | inference가 metadata에서 피처셋을 복원해 대조, 다르면 실패 | `inference.py`, 설계서 05 6.2절 |

### 4.1 clip의 방향이 왜 중요한가

예측값을 `[0, capacity]`로 자르는 것은 물리적으로 정당하다 — 발전량은 음수일 수 없고
설비용량을 넘을 수 없다. 그러나 **실제값에 같은 처리를 하면 평가 자체가 왜곡된다.**
실제값을 조정하면 그것은 전처리가 아니라 채점표 수정이다.

노트북 11은 holdout 실제값의 SHA-256을 실험 전후로 비교해 **한 번도 바뀌지 않았음**을
출력으로 남긴다. 이런 자기 감시 장치가 있어야 "실제값을 건드리지 않았다"가 주장이 아니라
증거가 된다.

## 5. 과적합 — 점수는 좋아지는데 실력은 아닌 경우

전처리를 다 지켜도 남는 위험이다.

### 5.1 같은 holdout을 반복해서 쓰는 비용

노트북 06·07·08·11에서 2024 holdout은 이미 여러 차례 피처 선택 근거로 쓰였다.
검증셋을 적응적으로(이전 결과를 보고 다음 후보를 정하는 방식으로) 반복 사용하면
그 추정치는 점점 낙관적으로 편향된다 — Dwork 등이 정리한 문제이며,
Blum과 Hardt는 리더보드 자체가 같은 구조를 갖는다는 것을 보였다.

**현재 위험도 평가**

| 항목 | 값 | 판단 |
|------|-----|------|
| 비교한 후보 수 | 8개 남짓 | 낮음 |
| 채택 후보의 개선분 | +0.015548 | 노이즈 수준을 크게 넘음 |
| 후보 간 최소 간격 | 약 0.00056 (nearest_own 0.589828 ↔ idw_p2_own 0.589269) | 이 정도 차이로는 순위를 확정하지 않는 편이 안전 |
| 향후 | GBM·fold·calibration으로 후보가 수십 개 | **위험 증가 예정** |

즉 지금까지의 결론은 유지할 만하지만, **후보가 늘어나는 다음 단계부터는 판단 기준을
옮겨야 한다.** 설계서 05의 Decision Box ⑮가 그 결정이다.

### 5.2 시계열에서는 단일 holdout 자체가 약한 근거다

Bergmeir와 Benítez는 시계열 예측 모델 평가에서 무작위 fold가 시간 의존성을 깨뜨리며,
blocked 또는 rolling 방식이 적절하다고 정리했다. 우리의 2024 단일 holdout은
시간 순서는 지키지만 **fold가 하나뿐**이라, 2024년이라는 특정 해의 기상 조건에
결과가 좌우될 수 있다.

이것이 다음 작업으로 seasonal/time fold(F1~F4)가 잡혀 있는 이유다.

### 5.3 local과 Public이 어긋날 구조적 이유 (이번 제출 한정)

| 이유 | 내용 |
|------|------|
| 결측 조건 차이 | 2024 holdout에는 결측이 없고 2025 test는 133개 컬럼에 있다. 제출물은 local이 겪지 않은 조건에서 예측한다 |
| 지표가 계단 함수 | 개선분의 79.6%가 FICR에서 왔는데, FICR은 오차율 6%/8% 경계의 계단 함수라 임계값 근처에서 불안정하다 |
| 학습 구간 차이 | holdout 점수는 2022~2023 학습 모델의 것이고, 제출물은 2022~2024 전체 학습 모델이 만들었다 |

세 번째 항목은 누수가 아니라 **의도된 선택**이다(설계서 05 Decision Box ⑬).
다만 두 숫자를 같은 것으로 읽으면 안 되므로 ledger에 기준을 함께 적었다.

## 6. 용어 사용 규범

발표와 코드 리뷰에서 실제로 오해를 만드는 항목만 골랐다.

| 용어 | 이 저장소에서의 뜻 | 흔한 혼동 |
|------|-------------------|-----------|
| **validation / holdout** | 2024년 라벨 구간. 라벨이 있고 우리가 점수를 잴 수 있다 | test와 섞어 쓰면 "검증 점수"가 무엇인지 불명확해진다 |
| **test** | 2025년 제출 구간. **라벨이 없다.** 점수는 리더보드만 안다 | 코드에서 `test_matrix`는 "제출용 피처"라는 뜻이지 "평가셋"이 아니다 |
| **forecast_kst_dtm** | 예보가 가리키는 **대상 시각** | 예보를 만든 시각이 아니다 |
| **data_available_kst_dtm** | 예보를 **손에 넣은 시각**. cutoff 판정의 기준 | 관측 시각이 아니다 |
| **lead time** | 위 둘의 차이(시간). 피처로 쓴다 | 예보 horizon과 같은 말이지만, 우리 코드에서는 `*_lead_hour` 컬럼 하나를 가리킨다 |
| **정규화(normalization)** | 이 저장소에서는 **쓰지 않는다.** RandomForest는 스케일 불변이다 | 표준화(standardization)와 혼용하는 사례가 많다. 안 쓰는 것을 썼다고 말하지 않는 것이 중요 |
| **NMAE** | 절대오차를 **설비용량으로** 나눈 값의 평균 | 실제값으로 나누는 MAPE가 아니다. 분모가 다르다 |
| **평가 대상 행** | 실제값이 설비용량의 **10% 이상**인 시각만 | 전체 8,760행이 아니다 (`metrics.py`) |
| **FICR** | 오차율 6% 이하 단가 4.0, 8% 이하 3.0, 초과 0으로 계산한 정산 비율 | 연속 지표가 아니라 **계단 함수**다 |
| **superset / target별 컬럼** | own-group 프리셋에서 조립은 550개, 학습은 target별 396개 | "피처 550개로 학습했다"는 표현은 own-group에서는 틀리다 |

**표기 정밀도도 용어의 일부다.** 설계서에 적힌 `0.592485`는 6자리 반올림이며,
실제 계산값은 `0.5924854297224146`이다. 재현 게이트를 `1e-9`로 두면서 반올림된 값과
비교하면 정상 재현이 실패로 나온다 — 설계서 05 v1.1에서 이 문제를 정정했다.
