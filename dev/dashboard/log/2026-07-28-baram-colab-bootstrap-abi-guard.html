Colab 부트스트랩 — 진단 코드가 진단 대상에 걸렸다

2026-07-28 KST · 노트북 16 셀 0 · 브랜치 fix/mygithub05253-colab-bootstrap-abi-guard

무엇이 났나

노트북 16을 Colab에서 처음 돌렸다. clone·Drive 마운트·데이터 4종 확인까지 전부 지나간 뒤 버전 점검에서 죽었다.

  BAD  numpy          2.0.2  (기대 1.26.4)
ValueError: numpy.dtype size changed, may indicate binary incompatibility.
            Expected 96 from C header, got 88 from PyObject
  ... /usr/local/lib/python3.12/dist-packages/numpy/random/_pickle.py
      → numpy/random/mtrand.pyx in init numpy.random.mtrand()

원인 — 상태는 예상했고, 안내에 닿지 못했다

Colab 런타임은 첫 셀이 돌기 전에 이미 numpy 2.0.2를 import해 둔다. 거기에 pip로 1.26.4를 깔면 디스크와 메모리의 numpy가 갈린다 — 확장 모듈을 하나라도 새로 부르는 순간 위 ABI 오류가 난다. mtrand는 numpy 1.26.4 것(C header 96)이고 메모리에 올라간 dtype은 numpy 2.0.2 것(88)이다.

이 상태 자체는 부트스트랩이 이미 예상하고 있었다 — "런타임 > 세션 다시 시작" 안내와 RuntimeError가 준비돼 있었다. 문제는 그 안내를 내기 위한 점검 reportVersions()가 importlib.import_module()로 네 패키지를 전부 새로 불렀다는 것이다. pandas를 부르는 순간 numpy 확장 모듈이 로드되며 죽었고, 정작 출력해야 할 안내에 닿지 못했다.

고친 것 — 점검은 import 없이 한다

reportVersions(allowImport)로 바꿨다. 버전 출처를 둘로 나누고 출력에 함께 찍는다.

경로출처왜
이미 sys.modules에 있음로드됨새 import가 아니라 조회다. 결과를 좌우하는 것은 이 버전이다
Colab · 설치 직후설치본 (dist metadata)여기서 import하면 ABI 오류로 죽어 안내가 사라진다
로컬로드됨 (import 허용)버전을 갈아끼우지 않아 안전하고, 이 환경은 metadata가 부정확하다(아래)

로컬에서 metadata를 믿으면 안 되는 이유. 이 개발 환경의 dist-info는 실제 설치본과 어긋나 있다 — pandas-2.2.2.dist-info가 남아 있는데 import되는 것은 3.0.3이고, scikit-learn은 metadata 1.5.1 / 실제 1.9.0이다. 그래서 로컬 경로는 종전대로 import해서 본다.

안내도 드리프트 출처별로 갈랐다. 재시작으로 풀리는 것과 아닌 것은 다른 문제다.

  • 로드됨 드리프트 → 런타임 재시작 안내 (디스크는 이미 고정본이다)
  • 설치본 드리프트 → 재시작해도 안 풀린다. pip install --force-reinstall 명령을 만들어 찍는다
  • loadedVersion의 except ImportError → except Exception. ABI 오류는 ValueError라 종전 코드는 잡지 못했다

남은 위험

재시작 뒤 pandas 3.0.3 리눅스 휠이 numpy 1.26.4에서 import되는지는 Colab에서만 확인된다. 같은 조합이 로컬(Windows·py3.12)에서 노트북 15를 33분 돌렸으므로 조합 자체는 성립한다. 실패하면 셀 1이 아니라 셀 3의 import pandas에서 드러난다.

손대지 않은 것

  • 노트북 15의 같은 코드 — 실행 출력이 이미 있는 노트북의 소스를 고치면 소스와 출력이 갈린다. 15의 Colab 경로는 한 번도 실행된 적이 없다(고정 커밋이 삭제된 브랜치를 가리켜 도달하지 못했다)
  • PINNED_COMMIT — 여전히 None이다. 이번 실행이 보고한 SHA는 982a815이며, 실제 실행이 끝난 뒤 그 SHA로 채우는 것이 설계 의도다
  • 기존 clone 갱신 — /content/baram이 있으면 pull하지 않는다. 이번 변경은 노트북 파일 안에만 있어 clone 상태와 무관하다
